# Agent rows use Copilot's session name

A row that stands for exactly one Copilot session is titled with that session's name, read from the `name:` field of Copilot's `~/.copilot/session-state/<session-id>/workspace.yaml`. This applies to an unmanaged surface row with one session, a session row, the hover card, the details inspector, the Active window footer, the Taskboard card, and Beat targets. Managed rows keep their launch label. Plain terminals, browsers and other surfaces keep the CMUX title.

The sidebar reads only that one field, through its existing read-only grant on `/.copilot/session-state/` and only for an exact session UUID the reader has already bound and verified (ADR 0001, ADR 0002). The read uses the reader's descriptor-anchored pattern: `O_NOFOLLOW`, owner check, regular file only, at most 16 KiB, and the file's stat must not change during the read. A strict parser takes only a top-level `name:` plain or quoted scalar on a single line. Lines that continue a top-level quoted value of another key are skipped. Block, multi-line, flow, tagged, aliased, null, duplicate or malformed values mean the name is unavailable. Control characters (Cc) and bidirectional controls are removed; other format characters such as ZWJ and ZWNJ are kept. The result is capped at 200 characters. The name is cached per session UUID and is re-read only when the file's identity, size or modification time changes, at the existing polling cadence. A brief read failure keeps the cached name.

Why: Copilot sets the CMUX terminal title to `<session name> - <status>`, so rows repeated a status the row already shows. A user-chosen name (`user_named: true`) is a title. An automatic name (`user_named: false`) is generated from the session's first prompt and may reproduce it verbatim, up to the 200-character cap. Showing it is a narrow exception to the rule against displaying observed session prompts: the sidebar shows only what the CMUX terminal title already shows for the same session, so there is no new exposure. No other prompt, transcript, tool argument or result is read. The owner approved this exception on 2026-10-14. The owner accepts that automatic names come from the first prompt. The intended workflow is to rename sessions explicitly; a user-chosen name then replaces the automatic one.

Rejected: splitting the terminal title on " - ". Showing only user-chosen names, since that would hide the same text the terminal title already shows. A name can contain " - ", and a title is not identity evidence (ADR 0002). Reading any other `workspace.yaml` field, or adding a YAML dependency.

Consequence: when the name is unavailable (missing, malformed, oversized, symlinked, unverified identity, or a dead or ambiguous session), the row shows the CMUX title unchanged. During observation loss, a row keeps the last name read for its exact session. Renaming the CMUX tab no longer changes a named Copilot row's title; renaming the Copilot session does. The workspace rename reminder (ADR 0017) is unchanged. Work-context session rows keep their "Session context" label.

Amendment (2026-10-16, #252): a born-managed root ([ADR 0025](0025-copilot-sessions-started-in-cmux-are-born-managed.md)) has no launch label. Its row uses its exact session's name under the same rules and the same eligibility check as managed session matching: one live, fresh observation of that session UUID in its workspace and surface, in a ready or partial tree, or during observation loss the last name read while its grace lasts. Dead, stale, ambiguous or misplaced evidence names nothing, and the row shows `Copilot session`. The name is presentation only; the projected label is unchanged. Launched rows keep their launch label.

Amendment (2026-10-18, #259): Work-context session rows no longer exist, so no row keeps the "Session context" label.
