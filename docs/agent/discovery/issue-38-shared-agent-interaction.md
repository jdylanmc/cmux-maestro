## Decisions

- Operator: P0 is cross-agent messaging among participating Copilot sessions in the same workspace, independent of selected surface, selected workspace, app activation, or other open workspaces.
- Operator: every message has a destination, body and sender return address; a reply is another fire-and-forget message. UDP-style describes semantics, not a requirement for UDP sockets.
- Operator: defer prompt scheduling to Copilot. No custom busy-state scheduling, acknowledgements, receipts, retries, or completion tracking in the first pass.
- Operator: delivery must not steal focus or interfere with human typing or unsent drafts. Focus is not a general delivery gate for a draft-independent messaging path.
- Operator: direct provider-native delivery is a candidate; Orca-style inbox with a check-command notification is an alternative. Beats may later use the same delivery path; no timer feature in this slice.
- Operator: Maestro is the orchestration product, sidebar one interface; use existing controller and pinned launcher. A necessary companion helper is allowed.
- Operator: fresh isolated branch; no revival of PR #53; guidance and documentation accompany code, no prose-only commits.
- Operator explicitly aligned this simplified first pass, requested continuation, and authorized needed research and coordination within CMUX while awaiting a feature PR.
- Host changes and replacement of the active installed integration are not automatically authorized. Discuss options if either becomes necessary.

## Constraints

- No focus stealing, workspace switching, app activation, terminal keystroke interference or draft submission as a delivery side effect.
- Use existing pinned account/model launch settings and preserve existing tool restrictions. Never publish credentials or private control material.
- No custom receipts, acknowledgements, resend policy, busy-state scheduler or completion tracker. Provider API acceptance may be reported accurately, not elevated to consumption or task completion.
- Maintain exact participating workspace/session identity and a usable return address; same-workspace messaging does not confer process control or extra tool privileges.
- No timer implementation, broad control-plane buildout, signing/provisioning ceremony or restoration of the abandoned implementation.

## Assumptions

- The native Copilot extension/session interface is a candidate for prompt delivery that avoids the composer; its exact API and live draft behavior must be established.
- A minimal provider adapter can reuse current launch and installation boundaries; no new generic runtime framework is presumed necessary.

## Contradictions

- Raw terminal input may conflict with human typing; background visibility alone is not proof of draft safety. A separate provider delivery path avoids assuming that terminal writes are necessary.
